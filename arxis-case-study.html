ARXIS — AEC Architecture Traceability & Change Governance

A graph-theoretic engineering platform mapping multi-disciplinary architectural, structural, and MEP dependencies to prevent multi-million euro site rework and uncoordinated change propagation in complex capital projects.

1. Executive Summary & Mission

In large-scale Architecture, Engineering, and Construction (AEC) capital projects, managing design evolution across dozens of specialized contractors is a persistent challenge. A single structural revision can invalidate MEP (Mechanical, Electrical, Plumbing) routings, egress calculations, or fire safety approvals. When changes are communicated via disjointed drawings and informal email chains, uncoordinated discrepancies reach the construction site, resulting in massive rework and contentious contractual claims.

ARXIS was engineered at Arxa Group to establish structural integrity across capital project documentation. ARXIS enforces an institutional axiom: traceability does not grant approval. By representing project requirements, technical decisions, and digital assets as a Directed Acyclic Graph (DAG), ARXIS automatically traces the downstream ripple effects of any design change, locks dependencies to immutable version hashes, and mandates explicit RACI sign-offs before physical construction commences.

2. Strategic Industry Problem & Context

Global studies across mega-infrastructure and commercial real estate reveal that on-site rework represents between 5% and 12% of total construction costs. The root causes trace directly to documentation breakdown:

  • Fragmented Information Silos: Architectural models (Revit/ArchiCAD), structural calculations, and MEP ductwork layouts reside in independent software platforms without unified dependency mapping.
  • Silent Revision Desynchronization: Contractors frequently build on site using Revision C drawings while engineering leads are actively drafting Revision E to fix a load-bearing beam collision.
  • Accountability Vacuum: When field collisions occur, determining whether the error stemmed from an uncommunicated client change request or an unauthorized design departure is nearly impossible.

3. System Architecture & Graph Mechanics

ARXIS models project documentation as a formal mathematical graph, structured into four interconnected tiers:

Tier Node Entity Mathematical / System Schema Operational Function
Tier 1 Client Requirement REQ_ID, Mandate Source, Owner, Acceptance Metric Defines functional, spatial, and regulatory requirements (e.g., LEED, fire codes).
Tier 2 Engineering Decision DEC_ID, Upstream REQ, Trade-off Rationale, Lead Approver Formalizes design choices made by lead engineers to satisfy requirements.
Tier 3 Design Artifact ART_ID, Upstream DEC, Content Hash, File Version Links digital deliverables (BIM models, CAD sheets, MEP schedules, specs).
Tier 4 Change Request (ECR) ECR_ID, Target Node, Impacted Subgraph, Review State Initiates formal change impact analysis, computing affected downstream paths.

4. 5-Dimensional Multidimensional Model

ARXIS is designed around the Arxa Group Multidimensional Operating Model:

  • Technical Model: Directed Acyclic Graph (DAG) engine with cycle detection algorithms, topological sort for change impact paths, and cryptographic SHA-256 deliverable hashing.
  • Product & Operating Workflow: Governed by a multi-stakeholder RACI matrix:
    1. Project Director: Authorizes scope modifications and approves budget impact thresholds.
    2. Discipline Leads (Arch / Struct / MEP): Formulate and sign off on technical decisions within their engineering domain.
    3. Document Controller: Issues formal drawing baselines and locks revision manifests.
    4. General Contractor / Site Engineer: Verifies field execution against locked, approved version hashes.
  • Financial Model: Direct comparison of formal coordination overhead against catastrophic site rework expenses.
  • Risk & Governance Model: Strict enforcement of international Common Data Environment (CDE) standards:
    • ISO 19650 (Parts 1 & 2): Information management using Building Information Modelling.
    • FIDIC / AIA Contract Administration: Rigorous evidence logging for change orders and delay claim defense.
  • Scaling Roadmap: Direct integration with Autodesk Construction Cloud (BIM 360), Procore, and Bentley ProjectWise via IFC schema adapters.

5. Data Contract & Anomaly Control Matrix

To eliminate silent errors, ARXIS enforces deterministic data invariants across the project graph:

Condition Observed Graph Anomaly Deterministic System Response
Missing Deliverable Link A Requirement links to a Decision with no associated Artifact Fails completeness audit; blocks project baseline release.
Dangling Identifier An Artifact references an uncertified or deleted Decision ID Rejects input immediately; flags integrity error.
Revision Desynchronization Change Request submitted against a superseded drawing version Pauses review workflow; mandates re-basing against current baseline.
Unauthorized Sign-off Actor lacks registered authority for the specific discipline Strictly denies authorization; flags security exception in audit log.

6. Coordination Economics & Rework Prevention

ARXIS grounds engineering governance in capital project economics:

  • Governance Coordination Cost: A formal multi-disciplinary change review requires approximately 4 hours of professional lead time @ €60.00/hour plus €10 allocated software tooling = €250 per change event (or €490 for complex 8-hour reviews).
  • Field Rework Exposure: In physical construction, a detected clash between structural beams and HVAC risers discovered during site assembly costs an average of €50,000 to €250,000 in emergency fabrications, equipment idle time, and schedule delay penalties.
  • Return on Governance (ROG): Preventing a single major clash through formal graph-based impact review yields a return exceeding 200× to 1000× the coordination cost of the review.

7. Empirical Verification & Benchmark Suite

The platform is validated via 7 automated regression test suites in the public GitHub repository (arxis-traceability):

  • Graph Structural Completeness: Confirms 100% dependency coverage across multi-tiered project fixtures.
  • Topological Change Reachability: Demonstrates that updating an upstream architectural requirement correctly tags all downstream structural and MEP deliverables as "Pending Re-evaluation".
  • Strict Negative-Case Handling: Proves that duplicate IDs, unauthorized sign-off actors, version mismatches, and cyclical references are deterministically rejected with zero silent fallbacks.

8. Standards Alignment & Scaling Roadmap

ARXIS serves as an architectural blueprint for next-generation infrastructure management. Strategic development bridges include:

  1. Industry Foundation Classes (IFC 4.3): Direct ingestion of open BIM schemas to automatically extract geometric spatial boundaries and building element GUIDs into the dependency DAG.
  2. Smart Contract Change Orders: Binding approved engineering change requests to digital escrow accounts for instant milestone disbursement.
  3. Predictive Schedule Impact Modeling: Integrating Critical Path Method (CPM) algorithms to forecast project completion date variance dynamically as changes are proposed.
